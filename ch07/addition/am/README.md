
## A Categorical Abstract Machine in C: `catmachine`

*An amalgamation of category theory and concatenative language design, expressed in portable C.*

This is not suppose to be a programming language.
The machine demonstrates that the boundary between
mathematical structure and executable code can be
made very "thin". It can be thin enough to compile
in C with gcc -O2 and run in milliseconds.

`catmachine.c` is a single-file implementation of
a small abstract machine that sits at the intersection
of two usually separate worlds: *category theory*
as a mathematical foundation for computation, and
*concatenative languages* (Forth, Joy, Factor, Cat)
as a practical model of stack-based program composition.

The result is not quite a language, not quite a
library--it is a *demonstrable theoretical object*.
Every construct in the code has a precise categorical
meaning, and every categorical concept has a concrete,
runnable C representation.

However, the ideas have applications if we extend
the ideas further. One such use is in relation to
the φ-node problem in manufacturing SSA
([ch05, SSA](./../../../ch05/sec5.7.1/ssa/)).
It is not easy, and can easily go wrong when the
semantics is not clear for the IR. Using linear
logic we can avoid the hack that φ-node introduce.
Exactly this is what can be observed in `linear_ssa.c`.


### The Two Traditions It Draws From

#### Concatenative Languages

Languages like Forth and Joy represent programs as sequences of words that transform a stack.
There are no named variables and no explicit argument passing - composition *is* juxtaposition.
The program `3 4 add dup mul` means: push 3, push 4, add them, duplicate the result, multiply.
The semantics are entirely determined by the order of words.

This is elegant, but usually left informal. Words have *stack effects* (how many values they
consume and produce), and programmers track these mentally or with ad hoc annotations.
Type systems for concatenative languages exist--Kitten, Cat, and the theoretical work of
Manfred von Thun on Joy--but rarely appear in implementation.

#### Category Theory

[Category theory](./../../../ch08/addition/category/) provides a precise language for
composition. A *morphism* `f : A → B` is an arrow between objects. Two morphisms compose
when the output type of one matches the input type of the next: if `f : A → B` and `g : B → C`,
then `g ∘ f : A → C`. A *symmetric monoidal category* adds a tensor product `⊗` that lets
morphisms operate in parallel on disjoint "regions" of structure. A *Cartesian category*
additionally permits copying (diagonal map `Δ : A → A ⊗ A`) and discarding
(terminal map `! : A → I`). *Linear categories* remove both, forcing every
resource to be used exactly once.

Concatenative languages are, in this light, programs in the *free symmetric monoidal category*
generated by a chosen set of primitive morphisms. This connection was made explicit by researchers
including Zinovy Diskin and Uwe Wolter, and more recently by the work on *string diagrams*
for monoidal categories.



### The Amalgamation: How They Meet Here

The machine makes this connection explicit and executable.

| Concept | Category Theory | This Machine |
|---------|-----------------|--------------|
| Object | A type `A` | An implicit stack configuration |
| Morphism `f : A → B` | Arrow between objects | `void (*)(Stack*)` with effect annotation |
| Composition `f ; g` | Sequential arrow chaining | `prog_append` with effect checking |
| Tensor `f ⊗ g` | Parallel morphisms on `A ⊗ B` | `tensor_run` with stack region slicing |
| Identity `id : A → A` | No-op arrow | `fn_id` |
| Braiding `σ : A ⊗ B → B ⊗ A` | Symmetry isomorphism | `swap` |
| Diagonal `Δ : A → A ⊗ A` | Cartesian copy map | `dup` |
| Terminal `! : A → I` | Cartesian discard map | `drop` |
| Quotation `[f]` | Reified morphism as value | `VAL_QUOT` on the stack |
| `eval : Hom(A,B) ⊗ A → B` | Counit of currying adjunction | `apply` |
| Kleisli arrow `f* : A → T(B)` | Morphism in Writer monad | `KleisliMorphism` with trace |
| Linear type discipline | `!`-free fragment of linear logic | `LinearStack` with consumption flags |
| Church numeral `n` | Initial algebra of ℕ | `church(n)` quotation applied `n` times |

The key insight is that *a concatenative program is a morphism expression in a monoidal category*.
Writing `dup add` is exactly writing the composition `add ∘ (Δ ⊗ id)`. The stack is the tensor
product of its inhabitants. Execution is morphism evaluation.



### What Runs in the Machine

*Demo 1 - Sequential composition* shows effect checking at build time:
`3 4 add dup mul` is verified to have net effect `(0 → 1)` before a single value is touched.

*Demo 2 - Tensor product* runs `f ⊗ g` on genuinely disjoint stack regions:
`add` on `(1, 2)` and `mul` on `(3, 4)` produce `(3, 12)` in parallel, with no interference between the sub-stacks.

*Demo 3 - Quotations* puts a morphism on the stack as a value, then applies it with `apply`.
This is the bridge to lambda calculus: a quotation `[dup mul]` is a first-class morphism reified as data,
applied via the categorical `eval` map.

*Demo 4 - Kleisli composition* threads computation through the Writer monad.
Each morphism emits to a trace log; `>=>` sequences two Kleisli arrows into one,
accumulating the log. The string diagram trace makes the compositional structure visually explicit.

*Demo 5 - Linear discipline* enforces that every pushed value is consumed exactly once.
A clean computation passes silently; leaving a value on the stack at the end raises
`LINEAR VIOLATION`--the machine's enforcement of the `!`--free fragment of linear logic.

*Demo 6 - Type error detection* rejects a morphism composition at build time when effect
arities are incompatible. `mul` (needs 2) cannot follow `dup ; drop` (net `1 → 1`).
The rejection happens before execution.

*Demo 7 - Church numerals* encodes `5` as a quotation applied five times to a base value:
`church(5)(+1)(0) = 5`. This is the initial algebra of the natural number object--the
categorical foundation of primitive recursion.



### What This Could Be Used For

This machine is not production software!
It is a *theoretical workbench*--but a workbench with real practical *directions*.


#### Compiler Intermediate Representation Design

Compilers need to reason about how operations consume and produce values.
The effect system here--where every morphism carries `(consume, produce)` arity--is
a simplified version of what Haskell's STG machine, GHC's Core, or LLVM's SSA form
track implicitly. A monoidal IR makes the dataflow graph explicit: morphisms are nodes,
composition is edges, tensor is parallel paths. String diagram rewriting then
becomes a principled basis for optimisation passes.

#### Quantum Circuit Simulation

Quantum circuits are morphisms in a *dagger compact category*--a monoidal category
with an additional adjoint structure. Every quantum gate is a morphism, circuits
compose sequentially, and qubits are tensored. The `tensor_run` implementation here
is structurally identical to how a quantum simulator must route qubits to gate inputs.
Replacing `double` with complex amplitudes and enforcing the linear discipline
(no cloning, no deletion--the no-cloning theorem) would yield a toy quantum
circuit interpreter.

#### Dataflow and Stream Processing

Dataflow systems like Apache Flink or reactive frameworks model computations as
graphs where nodes are functions and edges carry data. The tensor product here
is exactly the "fork" operation in a dataflow graph. The linear discipline maps
to backpressure: a value not consumed is a blocked channel.

#### Educational Tool for Type Theory

The effect system `(consume → produce)` is a baby version of *row-polymorphic stack types*,
the approach used by the Kitten and Cat languages. Extending `Effect` from a pair of
integers to a pair of type rows would give a full Hindley-Milner-style type system
for concatenative programs. This machine provides the minimal scaffold to experiment
with that extension without the overhead of a full language implementation.

#### Proof Assistants and Term Rewriting

String diagrams--the graphical calculus for monoidal categories--have a direct computational
interpretation as rewrite systems. A program in this machine is a term in a free monoidal
category. Equational reasoning (e.g., `swap ; swap = id`, or `dup ; drop = id`) becomes
a rewrite rule that can be applied to optimise or verify programs. Connecting the trace
output to a rewriting engine would give a small proof-carrying compiler.

#### Linear Logic Runtime Models

Linear type systems are used in Rust's borrow checker, in session types for protocol verification,
and in resource-aware programming. The `LinearStack` here is the simplest possible enforcement
of the linear discipline. Extending it with *affine* types (use at most once) or *relevant*
types (use at least once) by adjusting the consumption flags would give a direct model for these systems.



### Building

```
gcc -O2 -o catmachine catmachine.c
./catmachine
```

No dependencies. C99 or later.
The only headers used are `stdio.h`, `stdlib.h`, `string.h`, `stdarg.h`, and `assert.h`.

The design draws on several lines of work:
* Lambek, J. (1958). The mathematics of sentence structure. The American Mathematical Monthly, 65(3), 154–170. https://doi.org/10.2307/2310058
* Lawvere, F. W. (1963). Functorial Semantics of Algebraic Theories (Doctoral dissertation, Columbia University). (Republished in Reprints in Theory and Applications of Categories, No. 5 (2004) pp. 1–121).
* Girard, J.-Y. (1987). Linear logic. Theoretical Computer Science, 50(1), 1–101. https://doi.org/10.1016/0304-3975(87)90045-4
* Mac Lane, S. (1971). Categories for the working mathematician. Springer-Verlag. https://doi.org/10.1007/978-1-4757-4721-8

* Abramsky, S., & Coecke, B. (2004). A categorical semantics of quantum protocols. Proceedings of the 19th Annual IEEE Symposium on Logic in Computer Science (LICS'04), 415–425.

### Further Extensions

The code is structured to invite extension. Natural next steps include replacing
`(int, int)` effects with proper row-polymorphic types, implementing true string
diagram equality checking as a rewrite system, adding a dagger functor to the
morphism table for reversible/quantum computation, building a small REPL that
parses concatenative syntax into `Program` objects at runtime, and connecting
the Kleisli layer to a genuine side-effect system (IO, state, exceptions) rather
than just tracing.
