
## Lean Philosophy

### 1. What is the Lean Philosophy?

The *Lean Philosophy* is a systematic approach to design,
production, and organisational improvement that focuses on:
* Maximising value
* Minimising waste
* Continuous improvement
* Fast feedback cycles
* Respect for people

Core idea: Deliver value efficiently by eliminating activities that do not contribute to the intended outcome.

Lean is both:
* An operational philosophy
* A methodological framework


### 2. Historical Roots

#### Toyota Production System (TPS)

Lean originates from the *Toyota Motor Corporation* and the development of the:
* *Toyota Production System (TPS)*

Key contributors include:
* *Taiichi Ohno*
* *Shigeo Shingo*

They introduced concepts such as:
* Just-In-Time (JIT)
* Jidoka (automation with human judgment)
* Waste elimination


#### Diffusion into Other Domains

Lean principles later influenced:
* Manufacturing
* Software development (Lean Software)
* Product development
* Startups (Lean Startup)
* Healthcare, services, public sector

Popularised by:
* *James P. Womack*
* *Lean Thinking*


### 3. Purpose of Lean

Lean aims to:
1. Deliver *customer-defined value*
2. Eliminate *waste (muda)*
3. Improve *flow*
4. Enable *continuous improvement (kaizen)*
5. Build *adaptive, learning systems*


### 4. Why Use Lean?

#### Key Motivations

* Inefficiencies in processes
* Long development cycles
* Resource waste
* Quality issues
* Misalignment with user needs


#### Problems Addressed

* Overproduction
* Waiting/delays
* Unnecessary complexity
* Rework/defects
* Underutilised capabilities


### 5. Core Lean Concepts


#### Value

Defined by the end user or stakeholder.

Question: What activity directly contributes to the desired outcome?


#### Waste (Muda)

Typical categories:
* Overproduction
* Waiting
* Unnecessary processing
* Excess inventory
* Unnecessary motion
* Defects/rework
* Unused talent

In knowledge work/software:
* Feature bloat
* Premature optimization
* Excessive documentation
* Context switching


#### Flow

Work should progress smoothly without bottlenecks or interruptions.


#### Pull

Activities triggered by demand rather than forecasts.


#### Continuous Improvement (Kaizen)

Small, frequent refinements rather than sporadic large changes.


### 6. How Does Lean Work?

#### 1. Identify Value

* Define what stakeholders truly need
* Clarify success criteria

#### 2. Map the Value Stream

* Visualise all steps in a process
* Distinguish value-adding vs wasteful steps

Tools:
* Value Stream Mapping (VSM)


#### 3. Eliminate Waste

* Remove non-essential steps
* Simplify workflows
* Reduce delays


#### 4. Improve Flow

* Minimise handoffs
* Reduce batch sizes
* Address bottlenecks


#### 5. Establish Pull Mechanisms

* Trigger work by real demand
* Avoid speculative effort


#### 6. Continuous Feedback & Adaptation

* Measure outcomes
* Iterate rapidly
* Learn from failures


### 7. When Should Lean Be Used?

#### Appropriate Contexts

* Process optimisation
* Product/system development
* Innovation under uncertainty
* Resource-constrained environments
* Continuous delivery contexts


#### Less Suitable When

* Objectives are unclear
* No feedback mechanisms exist
* Change is structurally impossible


### 8. Lean vs Traditional Approaches

| Traditional Model | Lean Model                  |
|-------------------|-----------------------------|
| Plan-driven       | Feedback-driven             |
| Large batches     | Small increments            |
| Optimise locally  | Optimise flow               |
| Predict & control | Learn & adapt               |
| Tolerate waste    | Systematically remove waste |



### 9. Typical Outcomes

* Reduced cycle time
* Lower costs
* Improved quality
* Faster feedback
* Better alignment with needs


### 10. Lean Philosophy in Research & Design

Lean can function as:
* A development methodology
* A management philosophy
* A research strategy
  (especially for iterative artefact building)


#### Lean-Oriented Research Emphasises

* Early prototypes
* Rapid experimentation
* Minimum viable artefacts
* Continuous evaluation


### 11. Relevance to Sustainable Computing

Lean aligns strongly with sustainability goals.

#### Waste Reduction

* Energy waste
* Hardware overprovisioning
* Software inefficiency
* Idle resource consumption


#### Flow & Efficiency

* Efficient task execution
* Reduced computational overhead
* Simplified architectures


#### Small Iterations

* Incremental prototype refinement
* Fast feedback on energy/performance trade-offs


### 12. Lean + Frugal Engineering + DSR

These philosophies naturally reinforce one another:
* *Frugal Engineering* -> Design for minimal resources
* *Lean* -> Eliminate waste & optimise flow
* *DSR* -> Build & rigorously evaluate artefacts


### 13. Application to the Project

Lean principles could guide.


#### System Design

* Avoid overengineering
* Prioritise essential functionality
* Minimise idle energy consumption


#### Development Process

* Build minimal prototypes
* Test early energy/performance behaviour
* Iterate based on measurements


#### Evaluation

* Focus on value vs resource use
* Identify architectural waste
* Continuously refine


### 14. Methodological Interpretation

A Lean research/development approach:
1. Define value (sustainability + functional adequacy)
2. Build minimal viable architecture
3. Measure performance/energy
4. Eliminate waste
5. Iterate rapidly
